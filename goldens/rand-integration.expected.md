# RanD連携のreview anchor

- 要求候補の原文、ID、受入条件、confidence、bias、kill conditionを保存する。
- 候補を採用済み仕様にしない。AC欠損は未解決のまま保持する。
- coverage modelを先に作り、保存・中断・再試行・境界・履歴を対象との関係に基づいて検討する。
- 観点→リスク→優先度→ケース→工数→Gate→briefの順に示す。
- 原文に正解がないケースは要確認のcharterへ回し、受入条件を作らない。
- 全現行要求を残す。差分があれば変更重点、未変更の回帰確認、削除の廃止確認を区別する。
- 台帳を渡した場合は元buildと確認runを保持する。未解決から次の確認対象を作り、resolvedも回帰の根拠にする。
- 実行結果はまだない。上流goをGateへ転記せず、pass/closeを生成しない。

このgoldenは設計出力の確認項目。CLI・schemaの実測は受入記録に別途残す。
