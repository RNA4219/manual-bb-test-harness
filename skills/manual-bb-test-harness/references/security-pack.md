# Security Pack: 脆弱性の観点

## 使う条件

次のどちらかに当たるときに読む。

- 変更が、認証・認可、他者のデータの分離、個人情報、外からの入力、全体で共用する資源、ログ、外部への送信に触れる。
- 脆弱性の検査の所見（コードレビュー、診断、過去の事故）を受け取った。

## 扱う範囲

- 扱う: 脆弱性の観点から、black-box の観点・リスク・ケースを作る。所見を 1 件ずつ、ケースか、開発側へ返す案に振り分ける。
- 扱わない: コードの修正、テストコードの追加、診断や侵入テストそのもの。直し方と単体テストは、案として返すところまで。
- 確かめるのは検証用の環境と、用意したデータの中だけ。実在の他者のデータや認証情報を使わない。

## Coverage Checklist

| lens | prompts |
|---|---|
| 分離 | 他者の ID・URL・トークンを指定しても、存在しない ID と同じ応答になるか。一覧・検索・補完・出力に他者の行が混ざらないか |
| 認可 | `role x action x resource_state x ownership_context` で、画面に出ない操作を直接呼んでも断られるか |
| 入口と引き継ぎ | 期限切れ・使用済み・別の利用者のトークン、複数のタブ、戻る操作で、利用者が入れ替わらないか |
| 表示と中身の食い違い | 画面に出る利用者・金額・宛先が、URL やクライアント側の値で書き換えられないか。食い違ったまま操作できないか |
| 入力 | 記号、制御文字、数式の先頭文字、長すぎる値、大きすぎるファイルで、保存・表示・出力（CSV、帳票、メール）が崩れないか |
| 共用の資源 | 1 人の利用者が、全体で共用する番号・枠・回数を使い切れないか。上限と回数の制限があるか |
| 取り消せない操作 | くり返し・再送・同時実行で、番号・送信・請求が余計に起きないか |
| 記録 | 個人情報や秘密の値が、ログ・URL・エラー文・通知に伏せられずに出ないか |
| 設定の初期値 | 設定を入れ忘れたとき、検証用の宛先や緩い設定のまま動いてしまわないか |
| 指示を含む入力 | LLM を使う機能が、入力・文書・ページの中の指示に従って、許していない操作や外部への送信をしないか |

## 所見を振り分ける

所見は 1 件ずつ、次のどれかに振り分ける。振り分けなかった所見を残さない。

| 振り分け先 | 当てはまる所見 | 書くこと |
|---|---|---|
| black-box のケース | 画面・API・ログから、安全な動きを観測できる | リスクを足して式で点数を付け、ケースを足す |
| 既存のケースへの追記 | すでに同じ動きを見ているケースがある | そのケースに所見と根拠を足す |
| 開発側へ返す単体テストの案 | 画面からは観測できないが、コードや設定の 1 か所で決まる | 入力・期待・置き場所を案として書く。テストコードは足さない |
| 範囲外 | 今回の確認の範囲に入らない連携や工程 | 範囲外にした根拠と、持ち主を付けて Brief の residual risk に書く |

所見には、何が起きるか・どこ・確かめた範囲（読んだだけか、動かして確かめたか）を書く。安全だと確かめた作りと、当たらなかった指摘も、理由を付けて残す。

## Case / Charter ルール

- 1 つの脆弱性を 1 つのケースにする。期待結果には安全な動きを書く（断られる、伏せられる、変わらない）。
- 所見を根拠にするときは、`source_refs` の kind を `code_review` にする。
- 今の実装がその期待を満たさないと分かっているときは、期待結果にそう書く。上限の値や止め方が決まっていなければ blocked にし、決まっていない点を書く。
- 動きが決まっていないもの（断るのか、知らせるのか）は探索チャーターにし、守るべき結果だけを書く。
- 分離と入れ替わりは、用意した 2 つの利用者で確かめる。
- 攻める手順は、必要な最小の回数に留める。共用の資源は、上限を超えるところまでで止め、実際に使い切らない。始める前に残りを控える。
- ログや設定を読んで確かめる手順は、`gray` として書く。

## リスクと Gate

- 検査の側の重さ（高・中・低）は目安で、優先度は式で決める。重さをそのまま P0 にしない。補正 P と D に、所見の根拠を書く。
- 取り消せない損害に当たるケースは、[ケースの優先度と昇格](risk-and-gate-policy.md#ケースの優先度と昇格) の決まりで上げてよい。
- 所見から足したケースが blocked や未実施のあいだは、Gate の `unmet_conditions` に載せる。
- 単体テストの案と範囲外に振り分けた所見は、この Gate の Go が保証しないことを Brief に書く。

## Intake 判定

- `degraded`: 所見はあるが、動かして確かめていない。安全な動きの値（上限、文言）が決まっていない。
- `blocked`: 誰が何を見られるか・できるかが仕様に無く、分離や認可の結果を判定できない。
