# 分岐カバレッジ判定の訂正と不足テストの追加

2026-09-11。自己BBで見つかった3件の修正後、coverage.pyの行・分岐の合算値を分岐率として扱っていたCIを修正した。仕様を更新してから実装し、既定の全体85%・Gate専用90%を純粋な分岐率で検証する。

## ローカルでの結果

| 対象 | 修正前の分岐率 | 修正後の分岐率 | 基準 |
|---|---:|---:|---:|
| 全体 | 1,678/2,006 = 83.65% | **1,711/2,006 = 85.29%** | 85% |
| Gate専用 | 177/200 = 88.50% | **184/200 = 92.00%** | 90% |

全体1,168テスト成功（160.88秒）、Gate専用124テスト成功（9.32秒）。同じ分母のまま、未実行分岐をテストで減らした。除外追加、閾値引下げ、製品コード削除は行っていない。

参考として行カバレッジは全体91.32%、Gate専用96.60%。合算値は全体89.64%、Gate専用95.10%。**合算値を分岐率として表示・判定しない。** Windows/Python 3.13.7で実測した。GitHub Actionsの結果はPRに紐付いたrunを確認する。

## 実装

- [仕様](../specs/spec-08-hate-qeg-ci.md)に分岐率の式、丸め前の比較、不正件数・0分母・行のみ計測の拒否、旧証跡の扱いを明記した。
- `tools/ci/quality_evidence.py`に共通の件数検証・分岐率計算と`check-coverage`を追加した。captureの終了コード、QEGへ渡す検査結果、Gate専用workflowは同じ計算を使う。
- 収集を`manual-bb-ci/v2`、変換サマリを`manual-bb-hate-qeg/v2`にした。`coverage_metric=branch`と分子・分母・行率・分岐率・合算値を保存し、旧v1を分岐合格の証跡として受け付けない。
- `--cov-fail-under`の既存合算値チェックも補助条件として維持する。分岐の基準未達は、合算値が高くても非0終了する。

## 追加した検証

前回の1,117件から51件増加。Gateで入力欠落・risk/case/feature不一致と一方だけを明示する入力補完、Local Modeで根拠・追跡・工数・モバイル環境の不足を個別に検証した。ローカルAPIではUTF-8送信・認証ヘッダー・不正な応答JSON・欠落したmessage・分割content・不正設定をテストダブルで確認した。

CI境界は84.99%／85.00%／85.01%、合算値を100%にした低分岐率、不正型・欠測・0分母・不整合件数、旧収集版を検証した。pytestが成功でも分岐不足ならcaptureが失敗し、QEGへの検査結果もfailになる。

実LLMや外部業務サービスを呼ぶテストは追加していない。既存の3件は[修正受入](self-bb-fix-20260911/report.md)でBB45/45成功を確認済み。本追加で製品処理は変更せず、CI実装とテストを変更した。

## 証跡と限界

ローカルのcoverage JSON、pytest/JUnit、Gate結果とスナップショットは`branch-coverage-20260911/evidence.zip`と同ディレクトリのmanifestへ保存する。最初の[調査記録](self-bb-4.1.0/report.md)、[3件の修正記録](self-bb-fix-20260911/report.md)、[指標の訂正](self-bb-fix-20260911/coverage-audit.md)は保持する。

基準を満たしても全分岐を網羅したわけではない。全体295分岐、Gate専用16分岐が未実行であり、実LLM生成の意味的品質、実案件校正、手動受入を合格に読み替えない。今回はコード変更のPRとCI確認を対象とし、mainマージとPyPI公開は別の操作である。
