# manual-bb 4.1.0 自己ブラックボックス試験計画

対象: PyPI `bb-harness==4.1.0`（main `6149d81fee17b6271503717b3fc2c0f6a738a540`）。
manual-bb-test-harness Skillの観点→リスク→優先度→ケース→工数→Gate→briefの順で設計する。
期待結果を実行前に固定し、公開CLIを別プロセスとして操作する。製品内部の関数や既存単体テストは
期待値の計算に使わない。操作はCodexによる自動化であり、人の手動受入・独立レビューの代替とはしない。

対象環境はWindows、Python 3.13、新規venv、公開PyPI wheel。実案件データは使用せず、すべて合成入力。
要件評価・被覆・移行・Gate・Local Modeの通信前制御と、repo配布の実績分析ツールを対象にする。
実LLM生成の意味的品質は前回検収の未達を引き継ぐ。今回のLLM呼出先は操作数を数えるローカルテストダブルだけ。

## 工数

準備10分、ケース実行10分、証跡・差分レビュー15分、再現確認のbuffer10分、計45分を目安にする。
境界データは同じ手順をパラメータ化して実行する。アプリ内部テストの再実行件数へ混ぜない。

## Gate

profile=standard。未実行時点はno_go。P0全件pass、P1全件を今回の目標とし、high以上の未解決不具合0を
必要とする。既存の緑CIは補助証跡。今回の限定的なBB passを「不具合なし」や全環境のGoとは表現しない。
仕様解釈が必要なもの、未実施の実LLM品質・実案件校正は残余リスクとして明示する。

## Go/No-Go brief

実行後に結果、再現手順、影響、不具合と仕様確認の区別、修正優先度を`report.md`へ記録する。
この試験計画と結果は製品の挙動を変更せず、公開済み4.1.0への事後評価として残す。
