# カバレッジ指標の再確認

2026-09-11。ユーザーの「カバレッジが足りないのでは」という指摘を受け、保存済みcoverage JSONとCIの閾値判定を確認した。追加のテスト実行や製品変更は行っていない。

## 実測値

| 集計対象 | 行 | 分岐 | 行・分岐の合算 |
|---|---:|---:|---:|
| 全体1,117テスト | 4,675/5,174 = 90.36% | 1,678/2,006 = **83.65%** | 88.48% |
| Gate専用116テスト | 388/412 = 94.17% | 177/200 = **88.50%** | 92.32% |
| 全体テスト中のGateモジュール | 397/412 = 96.36% | 184/200 = 92.00% | 94.93% |

先の[修正検証記録](report.md)に記載した88.48%／92.32%は、coverage.pyの`percent_covered`であり、純粋な分岐率ではない。行数・分岐数を用いた合算値である。純粋な分岐率は`covered_branches / num_branches`から計算できる。

`.github/workflows/validate.yml`はジョブを「Overall branch coverage (85%)」「Gate branch coverage (90%)」と呼んでいるが、`--cov-fail-under`で合算値を検証している。`tools/ci/quality_evidence.py`も`coverage["totals"]["percent_covered"]`を使う。**名前のとおり分岐率85%／90%を要求すると、今回の全体・Gate専用の結果はどちらも未達**である。

「現在のCIコマンドの閾値を通る」という先の事実は変わらないが、それを「分岐の基準を満たした」「全体の検証が十分」と扱うことはできない。Gate専用と全体テストに含まれるGateの集計範囲も混同しない。

## 修正3件と残る範囲

今回変更した実行可能行に未実行行はなく、追加した分岐のうちcoverage.pyで測定される分岐にも未実行はなかった。日本語名・ASCII名、BOM有無、証跡0件・build欠落は対照試験で確認済みで、3件の再現解消は維持する。ただし、これは既存コード全体やすべての論理条件の網羅を意味しない。

全体には未実行499行・328分岐が残る。Local Modeのパイプラインは分岐189/234（80.77%）、要件評価は118/122（96.72%）、Markdown取込は46/50（92.00%）。配布物検証・artifact検証・Notion出力にも未実行が多い。

次の改善は、まずCI／HATEへの指標を行・分岐・合算で区別し、分岐の既定下限85%／90%を実際に検証すること。そのうえでGateの入力不正・版照合、生成の失敗・再試行・途中保存を優先し、期待動作を検証するテストで不足を埋める。閾値を下げたり除外を増やしたりして帳尻を合わせない。

元の証跡アーカイブとmanifestは変更していない。数値の根拠はアーカイブ内`coverage-all.json`と`coverage-gate.json`。本追記を、先のカバレッジに関する説明の訂正として扱う。
